# Output directory structure

What `output_dir` looks like after `experiment.run(output_dir=...)` (or `.arun()`)
finishes. Generated by `save_experiment_results()`
(`src/valtron_core/evaluation/model_eval.py`, on the generic `ModelEval` base
shared by every recipe) and `save_html_report()` (overridden per-recipe; the
concrete implementation is `ReferencedEval` in
`src/valtron_core/evaluation/referenced_eval.py`), which call `save_run_dir()` /
`save_single_model_result()` / `generate_report()` in `src/valtron_core/runner.py`.

```
output_dir/
  metadata.json              # documents, prompt, field/response-format config, cost totals
  progress.json              # live per-model doc counts, for external pollers (e.g. a dashboard)
  models/
    <model label>.json       # one file per model: predictions, metrics, llm_config
  html_report/                # only if "html" in config.output_formats
    evaluation_report.html
    detailed_analysis.html
    favicon.svg
  <output_dir-name>.pdf       # only if "pdf" in config.output_formats
```

`progress.json` (`src/valtron_core/progress.py`) is only written when
`output_dir` is set on the config itself, not when it's passed only to `.run()`.
It is left on disk after the run finishes (all models `"completed": true`)
rather than being cleaned up.

## Example

[`examples/metadata.example.json`](examples/metadata.example.json),
[`examples/model_result.example.json`](examples/model_result.example.json), and
[`examples/progress.example.json`](examples/progress.example.json) are real
output from a 3-document sentiment classification run against `gpt-4o-mini`
(see [`TYPES.md`](TYPES.md) for what each field maps to in code).

To reload a saved run directory back into a live instance:

```python
experiment = ClassificationExperiment.load_experiment_results("output_dir/")
```

## Class hierarchy behind this

`ModelEval` (`evaluation/model_eval.py`) is the generic, correctness-agnostic base
every recipe shares: construction, model management, data loading, preflight,
prompt prep, `_run_evaluations()`, persistence (`save_experiment_results()`),
traces, and a default `reevaluate()`. Its one required override is
`_evaluate_model_documents()` -- call a model, score its output. `ReferencedEval`
(`evaluation/referenced_eval.py`) is the concrete recipe for the classification/
extraction shape used by `ClassificationExperiment`/`ExtractionExperiment`:
scoring against a known label/`expected_value`, plus `save_html_report()`/
`save_pdf_report()`. See [`TYPES.md`](TYPES.md) for how each output file maps to
this hierarchy. A future task without a single ground-truth label -- e.g.
summarization -- would extend `ModelEval` directly as a sibling of
`ReferencedEval` instead of subclassing it. See
[`SUMMARIZATION_PLAN.md`](SUMMARIZATION_PLAN.md) for a concrete outline of
that.
